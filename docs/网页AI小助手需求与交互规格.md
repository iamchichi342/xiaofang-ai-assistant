# 网页 AI 小助手：需求与交互规格

## 1. 产品定位

这是一个运行在网页中的独立悬浮组件，不封装成 Electron、Tauri 或系统级桌面应用。

这里的“独立”指：

- 组件可以放入任意网页，不依赖页面的业务布局。
- 组件自身管理位置、眼神、菜单、会话和设置状态。
- 组件的 CSS、JavaScript 和数据结构尽量自包含。
- 后续可以封装成 Web Component，例如 `<ai-robot-assistant>`。
- 默认固定在浏览器视口内，不随页面内容滚动离开屏幕。

第一版继续使用当前的纯前端实现，API 请求先允许用户在网页设置中配置。正式上线时，不建议把长期 API Key 直接放在浏览器端，需要增加自己的服务端代理。

---

## 2. 核心使用流程

```text
网页加载
  ↓
机器人固定在视口角落
  ↓
鼠标移动：眼睛跟随，远处轻微转头
  ↓
右键机器人
  ↓
出现环形功能球
  ↓
机器人视线转向功能球
  ↓
用户点击功能球
  ↓
打开对应面板或会话气泡
```

组件需要同时处理两类目标：

1. 鼠标目标：机器人正常观察用户指针。
2. 功能目标：菜单展开后，机器人看向被选中的功能球。

功能球打开时，功能目标优先级高于鼠标目标；菜单关闭后，视线恢复跟随鼠标。

---

## 3. 右键功能菜单

### 3.1 触发方式

桌面端：

- 在机器人主体上点击右键。
- 阻止浏览器默认右键菜单。
- 机器人短暂压低或轻微停顿，表示菜单已经被唤醒。
- 以机器人为中心展开功能球。

移动端：

- 长按机器人约 `450ms` 触发。
- 触发前不能立即移动机器人位置。
- 长按过程中可以显示一个极轻的压缩反馈。

键盘辅助：

- 聚焦机器人后按 `Enter` 或 `Space` 打开菜单。
- 按 `Escape` 关闭菜单。
- 使用方向键在功能球之间移动焦点。

### 3.2 功能球数量与职责

第一版使用 3 个功能球：

| 功能球 | 图标语义 | 颜色 | 功能 |
|---|---|---|---|
| API 设置 | 齿轮 | 蓝色 | 配置服务商、接口地址、模型和 API Key |
| 人设/提示词 | 人物或魔法棒 | 紫色 | 修改系统提示词、名字、语气和行为边界 |
| 对话 | 对话气泡 | 绿色 | 打开会话输入框与回复气泡 |

功能球本身保持黑色圆形底，彩色只用于内部图标和微弱光晕：

```text
黑色圆球 = 组件统一视觉语言
彩色图标 = 功能识别
轻微彩色光晕 = 当前状态反馈
```

不建议使用大面积彩色按钮或带长文本的矩形菜单。这个机器人应该通过圆球、图标、颜色和视线表达功能，而不是出现一排传统设置按钮。

### 3.3 图标建议

使用现成图标库或内联 SVG，不手绘复杂图标：

- API 设置：`Settings` / 齿轮
- 人设：`UserRoundPen`、`WandSparkles` 或人物轮廓
- 对话：`MessageCircle` / `MessageSquare`
- 关闭会话：`X` 或 `MessageCircleOff`

图标必须提供 `aria-label` 和 `title`，鼠标悬停时显示简短提示。

## 4. 功能球位置规则

### 4.1 默认展开方向

根据机器人在视口中的位置自动选择展开方向：

| 机器人位置 | 默认菜单展开方向 |
|---|---|
| 右下角 | 向左上方展开 |
| 左下角 | 向右上方展开 |
| 右上角 | 向左下方展开 |
| 左上角 | 向右下方展开 |
| 视口中心附近 | 向距离最近的空白区域展开 |

不能固定写死为“永远向右展开”，否则机器人位于右侧时会把功能球推出屏幕。

### 4.2 坐标模型

以机器人中心为原点：

```js
menuCenter = robotCenter
menuRadius = robotSize * 0.95
```

3 个功能球沿一段弧线排列，不使用完全水平或垂直的一排：

```text
球 1：角度 205°
球 2：角度 245°
球 3：角度 285°
```

右下角机器人使用左上弧线时，实际角度需要根据展开象限翻转。球与球之间保持：

- 球直径：`38px～46px`
- 球间最小间距：`12px`
- 球心到机器人中心：`76px～104px`
- 球与视口边缘最小距离：`16px`

在小屏幕上，功能球直径降到 `36px`，菜单半径降到 `68px`，必要时改成半圆弧或纵向排列。

### 4.3 展开动画

功能球不要同时出现。建议采用错峰弹出：

```text
机器人压缩 80ms
第一个球出现 150ms
第二个球延迟 45ms
第三个球延迟 90ms
机器人视线依次扫过三个球
```

球的进入动作：

```text
scale(0.55) → scale(1.08) → scale(1)
```

不要使用过大的旋转和弹簧效果，功能菜单应该像机器人主动召唤出的工具，而不是普通下拉菜单。

### 4.4 点击菜单外部

- 点击页面其他区域：关闭功能球。
- 右键页面其他区域：关闭当前菜单，不打开浏览器菜单之外的组件菜单。
- 点击功能球：保持菜单打开，直到面板或会话被确认关闭。
- 按 `Escape`：关闭菜单。

## 5. 机器人视线规则

### 5.1 目标优先级

```text
主动表情动画 > 当前选中的功能球 > 最近悬停的功能球 > 鼠标位置 > 空闲动作
```

“主动表情动画”只在短时间内拥有最高优先级，例如点击成功、错误、惊讶和弹跳；动画完成后恢复看向当前功能目标。

### 5.2 视线切换

鼠标目标与功能球目标之间不能瞬移，应使用不同速度：

- 看向功能球：`180ms～280ms`
- 从功能球回到鼠标：`240ms～360ms`
- 功能球悬停时：眼睛锁定功能球，头部轻微跟随
- 功能球点击后：短暂看向面板标题或气泡位置

### 5.3 功能球悬停反馈

当鼠标进入某个球：

- 该球放大约 `8%`
- 彩色光晕增加
- 机器人先看球，再轻微转头
- 其他球降低透明度约 `15%`

当鼠标离开：

- 球恢复原尺寸
- 机器人视线回到菜单中心或鼠标

## 6. API 配置面板

点击蓝色齿轮球后，打开一个靠近机器人的轻量浮层，不使用全屏设置页。

### 6.1 字段定义

第一版字段：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---:|---|
| 服务商 | select | 是 | 例如 OpenAI 兼容接口、其他兼容服务 |
| API Base URL | text | 是 | 接口根地址 |
| API Key | password | 是 | 当前浏览器会话使用的密钥 |
| 模型 | text/select | 是 | 例如模型名称 |
| 测试连接 | button | 否 | 发送最小测试请求 |
| 保存 | button | 是 | 保存本次配置 |

### 6.2 网页端安全边界

纯网页版本可以实现配置和调用，但不能把长期 API Key 当成真正安全的秘密保存：

- 原型阶段：默认只保存到当前会话内存。
- 可选模式：用户明确选择后保存到 `sessionStorage`，关闭标签页后清除。
- 不使用 `localStorage` 保存长期 API Key。
- 不把 API Key 写入 URL、日志、错误信息或聊天记录。
- 正式部署：由网页请求自己的服务端代理，代理负责保存密钥并调用模型。

### 6.3 API 面板状态

```text
empty       尚未配置
editing     正在编辑
testing     正在测试连接
connected   测试成功
failed      测试失败
saved       已保存
```

状态反馈使用机器人表情：

- 测试中：困倦/思考式慢眨眼
- 成功：喜悦弧线 + 两次弹跳
- 失败：愤怒或悲伤，不建议同时使用错误红色大弹窗

## 7. 人设与提示词面板

点击紫色人设球后，打开人设编辑浮层。

### 7.1 字段定义

```text
助手名称
一句话身份
系统提示词
语气风格
回答长度
主动反馈开关
保存人设
恢复默认
```

推荐初始人设：

```text
你是一个只通过眼神、动作和简短气泡表达的网页小机器人。
你说话简洁、温和、有一点观察感，不要假装拥有网页之外的能力。
当用户没有明确问题时，保持简短，不主动连续发言。
```

### 7.2 人设和视觉状态的映射

人设不能直接控制任意 CSS，而是通过有限的表达事件调用机器人动作：

```js
assistant.setExpression("curious");
assistant.showMessage("我在看。");
```

模型输出建议转换为有限事件：

```text
thinking   → curious 或 sleepy
success    → joy
error      → sadness 或 anger
surprise   → surprise
idle       → neutral
```

这样可以避免 AI 直接返回一段代码来修改页面动画。

## 8. 对话功能球与会话

### 8.1 对话球随右键菜单出现

对话球与 API、人设功能球一致，只在右键菜单展开时出现。菜单关闭后，页面只保留机器人主体。再次右键可以查看对话球当前状态：

| 状态 | 外观 | 机器人表现 |
|---|---|---|
| closed | 绿色图标，黑色球 | 正常看鼠标 |
| open | 绿色图标变为关闭图标 | 看向输入气泡 |
| typing | 绿色呼吸光晕 | 好奇/思考 |
| streaming | 绿色脉冲 | 眼睛轻微跟随气泡 |
| unread | 外圈小亮点 | 短暂看向对话球 |
| error | 图标变为警示符号 | 悲伤或困惑 |

关闭会话不删除历史，只关闭当前气泡和输入框。再次右键机器人并点击对话球，可以恢复会话。

### 8.2 对话展开位置

对话气泡固定在机器人和对话球的相反侧，避免盖住功能球：

- 机器人在右侧：气泡向左展开。
- 机器人在左侧：气泡向右展开。
- 机器人在顶部：气泡向下展开。
- 机器人在底部：气泡向上展开。

建议宽度：

- 桌面端：`280px～360px`
- 移动端：`min(320px, calc(100vw - 32px))`

建议最大高度：`min(55vh, 520px)`，内部消息区域滚动。

### 8.3 气泡结构

```text
对话浮层
├── 机器人名称 + 当前状态 + 重新开始按钮 + 关闭按钮
├── 消息列表
│   ├── 用户消息
│   └── 机器人消息
├── 流式回答区域
└── 输入框 + 发送按钮
```

机器人回复出现在上方气泡中，不能替换成页面底部固定聊天栏。输入框只在对话球打开后出现。

对话浮层打开后，机器人保持中性表情。输入内容变化不重复触发表情动作，眼睛继续跟随鼠标；仅菜单、配置面板等明确交互目标可以临时接管视线。

### 8.4 会话关闭行为

右键展开菜单后点击对话球：

- `closed → open`
- 如果已有未读回复，先显示最新回复。
- 机器人看向对话面板。

再次右键展开菜单并点击关闭图标：

- `open → closed`
- 保留历史在内存中。
- 气泡淡出，机器人视线回到鼠标。

也可以直接点击对话标题栏右侧的关闭按钮，行为与右键菜单中的关闭会话一致。

点击气泡之外但仍在组件范围内：不关闭，方便用户继续操作。

### 8.5 重新开始对话

标题栏右侧提供圆形箭头图标按钮，悬停提示为“重新开始对话”。点击后：

- 立即中止仍在生成的回答。
- 清空用户消息、机器人消息和错误提示。
- 清空当前输入内容，不保留旧上下文到下一次 API 请求。
- 保持对话浮层开启，并将状态恢复为“等待输入”。
- 机器人短暂看向输入区，随后恢复鼠标跟随。

该操作不同于关闭会话：关闭会话保留历史，重新开始会永久清除当前页面内存中的本轮历史。

### 8.6 闲置模式

- 鼠标连续 1 分钟没有移动时，机器人自动进入闲置模式。
- 自动闲置期间仅停止跟随鼠标；表情、眨眼、拖动、菜单、聊天和面板功能保持不变。
- 鼠标再次移动后，自动闲置立即结束。
- 右键菜单右侧提供独立的“闲置 5 分钟”功能球。
- 手动闲置期间鼠标移动不会提前恢复，5 分钟结束后自动恢复。
- 手动闲置期间再次点击该功能球，可以提前结束闲置。
- 闲置球与左侧三个功能球使用同一个圆心和轨道半径，位置在机器人右上侧。
- 圆轨道在原有半径基础上继续向外增加约 `5mm`（网页中按约 `19px` 计算）。

## 9. 总状态机

```text
assistant
├── idle
├── tracking-pointer
├── context-menu-open
│   ├── menu-idle
│   ├── menu-hover-api
│   ├── menu-hover-persona
│   └── menu-hover-chat
├── api-panel-open
│   ├── api-empty
│   ├── api-editing
│   ├── api-testing
│   ├── api-connected
│   └── api-failed
├── persona-panel-open
├── chat-closed
├── chat-open
│   ├── chat-idle
│   ├── chat-typing
│   ├── chat-streaming
│   ├── chat-unread
│   └── chat-error
└── dragging
```

状态切换原则：

- 拖动时暂时关闭功能球悬停反馈，但不能清除会话。
- 打开 API 或人设面板时，功能球继续存在，点击同一球可以关闭面板。
- 对话打开时，再次右键可以看到变为关闭入口的对话球。
- 错误状态只影响当前请求，不应让整个组件失去拖动和菜单能力。

## 10. 推荐的前端模块拆分

```text
index.html
styles/
  global.css
  assistant.css
  menu.css
  panels.css
  chat.css
src/
  main.js
  state.js
  data/
    expressions.js
    menu-items.js
  components/
    ScreenAssistant.js
    ContextMenu.js
    FunctionBall.js
    ApiPanel.js
    PersonaPanel.js
    ChatBubble.js
  services/
    api-client.js
    session-store.js
  utils/
    math.js
    viewport.js
    focus.js
```

第一轮实现建议顺序：

1. `ContextMenu`：右键展开黑色彩色图标球。
2. `FunctionBall`：球的位置、碰撞和悬停。
3. `ScreenAssistant`：视线目标从鼠标切换到功能球。
4. `ChatBubble`：右键菜单中的对话入口和浮动回复气泡。
5. `ApiPanel`：先做浏览器会话级配置。
6. `PersonaPanel`：编辑人设并接入表情事件。
7. `api-client`：接入真实接口，先支持 OpenAI-compatible JSON 请求。

## 11. 第一版验收标准

### 菜单

- 右键机器人后，浏览器默认菜单不出现。
- 3 个功能球从机器人附近错峰展开。
- 每个球有黑色圆形底、彩色图标和明确 hover 状态。
- 功能球不会超出视口。
- 机器人会依次看向菜单球或当前 hover 球。
- 点击外部或按 `Escape` 可以关闭菜单。

### API

- 可以打开配置面板。
- 可以填写 Base URL、Key 和模型。
- 可以测试连接并显示成功/失败状态。
- 刷新页面后不默认恢复长期 API Key。

### 人设

- 可以编辑名称和系统提示词。
- 可以保存当前会话的人设。
- 可以恢复默认人设。
- 人设变更会影响下一次请求，而不是直接执行页面代码。

### 对话

- 菜单关闭后不显示任何功能球，只保留机器人。
- 点击对话球后，上方出现回复气泡和输入区。
- 回复出现在机器人上方或侧方的悬浮气泡中。
- 可以关闭会话，关闭后对话历史仍保留在当前页面内存。
- 可以在标题栏重新开始对话，清空历史并以新上下文继续。
- 请求中、成功、失败和未读状态有不同视觉反馈。

---

## 12. 暂不做的内容

第一版暂不加入：

- 系统级桌面置顶。
- Electron/Tauri 封装。
- 多窗口同步。
- 用户账号和云端人设同步。
- 永久保存 API Key。
- 复杂语音输入和语音播报。
- 让 AI 直接控制任意前端 CSS 或执行任意代码。

这些内容会显著扩大安全和产品边界，等网页交互闭环稳定后再评估。

## 13. 实现记录

### 2026-11-19：网页 AI 助手交互闭环

已完成：

- 右键机器人展开 API、人设和对话三个黑色功能球。

验证结果：
