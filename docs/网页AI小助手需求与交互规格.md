# 小方 AI 助手：产品需求与交互规格

## 1. 产品定位

### 1.1 一句话定义

> 小方是一个“会注意你”的轻量 AI 小助手：它通过眼神、表情和动作感知用户的操作，并让用户以最短路径配置自己的 API、开始一段简洁可控的 AI 对话。

### 1.2 完整产品定义

小方将“桌面角色的陪伴感”与“AI 工具的实用性”结合起来。它平时安静地停留在屏幕边缘，通过视线跟随、轻微转头、眨眼和表情变化回应用户；当用户需要帮助时，可以快速展开功能菜单、配置 OpenAI-compatible API、自定义人设并开始对话。

小方不是传统聊天窗口的缩小版。它的差异不在于承载更复杂的对话功能，而在于让 AI 在用户开口之前就表现出“正在注意”的状态，并在交互过程中用有限但一致的视觉语言反馈理解、等待、成功、失败和闲置。

角色的视觉表现、表情系统和动作动画完全由 HTML、CSS 与 JavaScript 实现，不依赖 3D 模型。AI 能力来自用户配置的兼容接口；“纯前端”特指角色呈现与交互层，不代表模型推理在本地浏览器完成。

### 1.3 目标用户

首要用户：

- 已有 AI API，希望快速获得独立轻量入口的开发者和高频 AI 用户。
- 不希望长期打开完整聊天软件，只需要随手提问、快速确认和简短辅助的桌面工作者。
- 重视角色感、陪伴感和情绪反馈，但不需要复杂虚拟形象或 3D 桌宠的用户。

次要用户：

- 希望在网站、产品演示或个人项目中嵌入互动 AI 角色的设计师与前端开发者。
- 需要验证“角色化 AI 交互”概念的产品团队。

### 1.4 用户问题

- 传统 AI 对话工具需要用户主动打开页面，AI 在未对话时几乎没有存在感。
- 普通桌面宠物有情绪表现，但缺少可持续使用的工具价值。
- 完整 AI 客户端功能较重，不适合嵌入当前工作流中的即时、短时交互。
- 自建 API 客户端通常只解决连接问题，缺少统一的人设、状态和视觉反馈。

### 1.5 核心价值

| 价值 | 产品表达 | 用户收益 |
|---|---|---|
| 注意感 | 眼睛跟随、远距离轻微转头、菜单目标注视 | 用户感到角色在关注当前操作 |
| 快速配置 | API、模型与人设集中在轻量浮层中 | 使用已有 API，减少接入成本 |
| 轻量对话 | 悬浮气泡、短路径唤起、流式回答 | 不离开当前页面或工作上下文 |
| 情绪反馈 | 有限表情与动作映射真实系统状态 | 不读文字也能理解等待、成功和失败 |
| 前端可扩展 | 视觉和动画由前端状态机驱动 | 易于调整、嵌入和二次开发 |
| 用户可控 | 会话关闭、重新开始、闲置与密钥会话级保存 | 降低打扰并明确数据边界 |

### 1.6 核心体验闭环

```text
被注意：机器人通过视线回应用户
  ↓
被召唤：右键展开功能球
  ↓
快速使用：配置 API / 人设或直接恢复对话
  ↓
获得反馈：流式回答与表情动作同步表达状态
  ↓
安静退出：关闭气泡或进入闲置，只保留小方主体
```

### 1.7 产品原则

1. **存在但不打扰**：默认安静，只有明确交互或关键状态才使用明显动作。
2. **表达服务于状态**：每个表情和动画必须对应可解释的系统状态，不能为了热闹随机抖动。
3. **两步内开始对话**：已配置用户从唤起菜单到输入内容不超过两次点击。
4. **角色语言一致**：黑色方形主体、圆形功能球、圆头等宽眼线和轻量气泡保持统一。
5. **配置权属于用户**：模型、人设、会话和闲置状态由用户控制，不替用户做不可逆决定。
6. **明确安全边界**：不承诺浏览器能够安全长期保存密钥，不让模型直接执行任意前端代码。

### 1.8 产品边界

小方当前重点解决：

- 低打扰的角色存在感。
- OpenAI-compatible API 的快速配置。
- 随手提问、解释、改写、确认等轻量 AI 对话。
- 用表情与动画表达交互和请求状态。

小方当前不定位为：

- 承载复杂任务编排的自主 Agent。
- 替代完整聊天历史、知识库和多会话管理的 AI 客户端。
- 能安全永久托管用户 API Key 的账号云服务。
- 高频主动弹窗、持续说话或抢占注意力的桌面宠物。

### 1.9 产品形态与技术策略

项目使用同一套前端组件支持两种形态：

- 组件可以放入任意网页，不依赖页面的业务布局。
- 组件自身管理位置、眼神、菜单、会话和设置状态。
- 组件的 CSS、JavaScript 和数据结构尽量自包含。
- 后续可以封装成 Web Component，例如 `<ai-robot-assistant>`。
- 默认固定在浏览器视口内，不随页面内容滚动离开屏幕。
- Windows 版本使用 Electron 提供透明、置顶、托盘和点击穿透能力，但角色逻辑仍复用网页前端代码。

当前版本允许用户在设置中直接配置 API。面向公开部署或多人使用时，应增加服务端代理，不把长期 API Key 直接交给浏览器保存。

### 1.10 第一阶段成功标准

- 新用户能够在 3 分钟内完成 API 配置并发出第一条消息。
- 已配置用户能够在两次点击内进入可输入状态。
- 鼠标、菜单和请求状态变化后，视觉反馈在 `100ms` 内开始响应。
- 打开对话后保持中性表情，不因连续输入重复触发抖动动作。
- 关闭对话或进入闲置后，界面恢复为低打扰状态。
- API Key 不进入仓库、URL、聊天记录或长期本地存储。

## 2. 核心使用流程

```text
网页加载或桌面组件启动
  ↓
机器人固定在视口角落
  ↓
鼠标移动：眼睛跟随，远处轻微转头
  ↓
右键机器人
  ↓
出现环形功能球
  ↓
机器人视线转向功能球
  ↓
用户点击功能球
  ↓
打开对应面板或会话气泡
```

组件需要同时处理两类目标：

1. 鼠标目标：机器人正常观察用户指针。
2. 功能目标：菜单展开后，机器人看向被选中的功能球。

功能球打开时，功能目标优先级高于鼠标目标；菜单关闭后，视线恢复跟随鼠标。

## 3. 右键功能菜单

### 3.1 触发方式

桌面端：

- 在机器人主体上点击右键。
- 阻止浏览器默认右键菜单。
- 机器人短暂压低或轻微停顿，表示菜单已经被唤醒。
- 以机器人为中心展开功能球。

移动端：

- 长按机器人约 `450ms` 触发。
- 触发前不能立即移动机器人位置。
- 长按过程中可以显示一个极轻的压缩反馈。

键盘辅助：

- 聚焦机器人后按 `Enter` 或 `Space` 打开菜单。
- 按 `Escape` 关闭菜单。
- 使用方向键在功能球之间移动焦点。

### 3.2 功能球数量与职责

第一版使用 4 个功能球，其中三个在机器人左侧弧线排列，闲置球位于右侧同一环形轨道：

| 功能球 | 图标语义 | 颜色 | 功能 |
|---|---|---|---|
| API 设置 | 齿轮 | 蓝色 | 配置服务商、接口地址、模型和 API Key |
| 人设/提示词 | 人物或魔法棒 | 紫色 | 修改系统提示词、名字、语气和行为边界 |
| 对话 | 对话气泡 | 绿色 | 打开会话输入框与回复气泡 |
| 闲置模式 | 月亮或暂停 | 黄色 | 暂停鼠标跟随 5 分钟，再次点击可提前恢复 |

功能球本身保持黑色圆形底，彩色只用于内部图标和微弱光晕：

```text
黑色圆球 = 组件统一视觉语言
彩色图标 = 功能识别
轻微彩色光晕 = 当前状态反馈
```

不建议使用大面积彩色按钮或带长文本的矩形菜单。这个机器人应该通过圆球、图标、颜色和视线表达功能，而不是出现一排传统设置按钮。

### 3.3 图标建议

使用现成图标库或内联 SVG，不手绘复杂图标：

- API 设置：`Settings` / 齿轮
- 人设：`UserRoundPen`、`WandSparkles` 或人物轮廓
- 对话：`MessageCircle` / `MessageSquare`
- 关闭会话：`X` 或 `MessageCircleOff`
- 闲置模式：`Moon` / `Pause`

图标必须提供 `aria-label` 和 `title`，鼠标悬停时显示简短提示。

## 4. 功能球位置规则

### 4.1 默认展开方向

根据机器人在视口中的位置自动选择展开方向：

| 机器人位置 | 默认菜单展开方向 |
|---|---|
| 右下角 | 向左上方展开 |
| 左下角 | 向右上方展开 |
| 右上角 | 向左下方展开 |
| 左上角 | 向右下方展开 |
| 视口中心附近 | 向距离最近的空白区域展开 |

不能固定写死为“永远向右展开”，否则机器人位于右侧时会把功能球推出屏幕。

### 4.2 坐标模型

以机器人中心为原点：

```js
menuCenter = robotCenter
menuRadius = robotSize * 0.95
```

四个功能球共享同一圆心和轨道半径，采用“左三右一”的结构：

```text
对话球：正左侧
API 球：左上侧，与水平线夹角约 26°
人设球：左下侧，与水平线夹角约 26°
闲置球：右上侧，与水平线夹角约 55°
```

当机器人接近视口边缘时，整组轨道需要向可用空间偏移，不能单独压缩某一个球的位置。球与球之间保持：

- 球直径：`38px～46px`
- 球间最小间距：`12px`
- 球心到机器人中心：`76px～104px`
- 球与视口边缘最小距离：`16px`

在小屏幕上，功能球直径降到 `36px`，菜单半径降到 `68px`，必要时改成半圆弧或纵向排列。

### 4.3 展开动画

功能球不要同时出现。建议采用错峰弹出：

```text
机器人压缩 80ms
第一个球出现 150ms
第二个球延迟 45ms
第三个球延迟 90ms
第四个球延迟 135ms
机器人视线扫过菜单中心，并在悬停后锁定目标球
```

球的进入动作：

```text
scale(0.55) → scale(1.08) → scale(1)
```

不要使用过大的旋转和弹簧效果，功能菜单应该像机器人主动召唤出的工具，而不是普通下拉菜单。

### 4.4 点击菜单外部

- 点击页面其他区域：关闭功能球。
- 右键页面其他区域：关闭当前菜单，不打开浏览器菜单之外的组件菜单。
- 点击功能球：保持菜单打开，直到面板或会话被确认关闭。
- 按 `Escape`：关闭菜单。

## 5. 机器人视线规则

### 5.1 目标优先级

```text
主动表情动画 > 当前选中的功能球 > 最近悬停的功能球 > 鼠标位置 > 空闲动作
```

“主动表情动画”只在短时间内拥有最高优先级，例如点击成功、错误、惊讶和弹跳；动画完成后恢复看向当前功能目标。

### 5.2 视线切换

鼠标目标与功能球目标之间不能瞬移，应使用不同速度：

- 看向功能球：`180ms～280ms`
- 从功能球回到鼠标：`240ms～360ms`
- 功能球悬停时：眼睛锁定功能球，头部轻微跟随
- 功能球点击后：短暂看向面板标题或气泡位置

### 5.3 功能球悬停反馈

当鼠标进入某个球：

- 该球放大约 `8%`
- 彩色光晕增加
- 机器人先看球，再轻微转头
- 其他球降低透明度约 `15%`

当鼠标离开：

- 球恢复原尺寸
- 机器人视线回到菜单中心或鼠标

## 6. API 配置面板

点击蓝色齿轮球后，打开一个靠近机器人的轻量浮层，不使用全屏设置页。

### 6.1 字段定义

第一版字段：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---:|---|
| 服务商 | select | 是 | 例如 OpenAI 兼容接口、其他兼容服务 |
| API Base URL | text | 是 | 接口根地址 |
| API Key | password | 是 | 当前浏览器会话使用的密钥 |
| 模型 | text/select | 是 | 例如模型名称 |
| 测试连接 | button | 否 | 发送最小测试请求 |
| 保存 | button | 是 | 保存本次配置 |

### 6.2 网页端安全边界

纯网页版本可以实现配置和调用，但不能把长期 API Key 当成真正安全的秘密保存：

- 原型阶段：默认只保存到当前会话内存。
- 可选模式：用户明确选择后保存到 `sessionStorage`，关闭标签页后清除。
- 不使用 `localStorage` 保存长期 API Key。
- 不把 API Key 写入 URL、日志、错误信息或聊天记录。
- 正式部署：由网页请求自己的服务端代理，代理负责保存密钥并调用模型。

### 6.3 API 面板状态

```text
empty       尚未配置
editing     正在编辑
testing     正在测试连接
connected   测试成功
failed      测试失败
saved       已保存
```

状态反馈使用机器人表情：

- 测试中：困倦/思考式慢眨眼
- 成功：喜悦弧线 + 两次弹跳
- 失败：愤怒或悲伤，不建议同时使用错误红色大弹窗

## 7. 人设与提示词面板

点击紫色人设球后，打开人设编辑浮层。

### 7.1 字段定义

```text
助手名称
一句话身份
系统提示词
语气风格
回答长度
主动反馈开关
保存人设
恢复默认
```

推荐初始人设：

```text
你是一个只通过眼神、动作和简短气泡表达的网页小机器人。
你说话简洁、温和、有一点观察感，不要假装拥有网页之外的能力。
当用户没有明确问题时，保持简短，不主动连续发言。
```

### 7.2 人设和视觉状态的映射

人设不能直接控制任意 CSS，而是通过有限的表达事件调用机器人动作：

```js
assistant.setExpression("curious");
assistant.showMessage("我在看。");
```

模型输出建议转换为有限事件：

```text
thinking   → curious 或 sleepy
success    → joy
error      → sadness 或 anger
surprise   → surprise
idle       → neutral
```

这样可以避免 AI 直接返回一段代码来修改页面动画。

## 8. 对话功能球与会话

### 8.1 对话球随右键菜单出现

对话球与 API、人设功能球一致，只在右键菜单展开时出现。菜单关闭后，页面只保留机器人主体。再次右键可以查看对话球当前状态：

| 状态 | 外观 | 机器人表现 |
|---|---|---|
| closed | 绿色图标，黑色球 | 正常看鼠标 |
| open | 绿色图标变为关闭图标 | 中性表情，继续看鼠标 |
| typing | 绿色呼吸光晕 | 中性表情，不因输入抖动 |
| streaming | 绿色脉冲 | 中性表情，继续看鼠标 |
| unread | 外圈小亮点 | 短暂看向对话球 |
| error | 图标变为警示符号 | 悲伤或困惑 |

关闭会话不删除历史，只关闭当前气泡和输入框。再次右键机器人并点击对话球，可以恢复会话。

### 8.2 对话展开位置

对话气泡固定在机器人和对话球的相反侧，避免盖住功能球：

- 机器人在右侧：气泡向左展开。
- 机器人在左侧：气泡向右展开。
- 机器人在顶部：气泡向下展开。
- 机器人在底部：气泡向上展开。

建议宽度：

- 桌面端：`280px～360px`
- 移动端：`min(320px, calc(100vw - 32px))`

建议最大高度：`min(55vh, 520px)`，内部消息区域滚动。

### 8.3 气泡结构

```text
对话浮层
├── 机器人名称 + 当前状态 + 重新开始按钮 + 关闭按钮
├── 消息列表
│   ├── 用户消息
│   └── 机器人消息
├── 流式回答区域
└── 输入框 + 发送按钮
```

机器人回复出现在上方气泡中，不能替换成页面底部固定聊天栏。输入框只在对话球打开后出现。

对话浮层打开后，机器人保持中性表情。输入内容变化不重复触发表情动作，眼睛继续跟随鼠标；仅菜单、配置面板等明确交互目标可以临时接管视线。

### 8.4 会话关闭行为

右键展开菜单后点击对话球：

- `closed → open`
- 如果已有未读回复，先显示最新回复。
- 机器人保持中性表情并继续跟随鼠标。

再次右键展开菜单并点击关闭图标：

- `open → closed`
- 保留历史在内存中。
- 气泡淡出，机器人视线回到鼠标。

也可以直接点击对话标题栏右侧的关闭按钮，行为与右键菜单中的关闭会话一致。

点击气泡之外但仍在组件范围内：不关闭，方便用户继续操作。

### 8.5 重新开始对话

标题栏右侧提供圆形箭头图标按钮，悬停提示为“重新开始对话”。点击后：

- 立即中止仍在生成的回答。
- 清空用户消息、机器人消息和错误提示。
- 清空当前输入内容，不保留旧上下文到下一次 API 请求。
- 保持对话浮层开启，并将状态恢复为“等待输入”。
- 机器人保持中性表情和鼠标跟随，不额外触发动作。

该操作不同于关闭会话：关闭会话保留历史，重新开始会永久清除当前页面内存中的本轮历史。

### 8.6 闲置模式

- 鼠标连续 1 分钟没有移动时，机器人自动进入闲置模式。
- 自动闲置期间仅停止跟随鼠标；表情、眨眼、拖动、菜单、聊天和面板功能保持不变。
- 鼠标再次移动后，自动闲置立即结束。
- 右键菜单右侧提供独立的“闲置 5 分钟”功能球。
- 手动闲置期间鼠标移动不会提前恢复，5 分钟结束后自动恢复。
- 手动闲置期间再次点击该功能球，可以提前结束闲置。
- 闲置球与左侧三个功能球使用同一个圆心和轨道半径，位置在机器人右上侧。
- 圆轨道在原有半径基础上继续向外增加约 `5mm`（网页中按约 `19px` 计算）。

状态切换原则：

- 错误状态只影响当前请求，不应让整个组件失去拖动和菜单能力。

## 11. 第一版验收标准

### 菜单

- 右键机器人后，浏览器默认菜单不出现。
- 4 个功能球从机器人附近错峰展开，左侧三个、右侧一个共享同一环形轨道。
- 每个球有黑色圆形底、彩色图标和明确 hover 状态。
- 功能球不会超出视口。
- 机器人会依次看向菜单球或当前 hover 球。
- 点击外部或按 `Escape` 可以关闭菜单。

### API

- 可以打开配置面板。
- 可以填写 Base URL、Key 和模型。
- 可以测试连接并显示成功/失败状态。
- 刷新页面后不默认恢复长期 API Key。

### 人设

- 可以编辑名称和系统提示词。
- 可以保存当前会话的人设。
- 可以恢复默认人设。
- 人设变更会影响下一次请求，而不是直接执行页面代码。

### 对话

- 菜单关闭后不显示任何功能球，只保留机器人。
- 点击对话球后，上方出现回复气泡和输入区。
- 回复出现在机器人上方或侧方的悬浮气泡中。
- 可以关闭会话，关闭后对话历史仍保留在当前页面内存。
- 可以在标题栏重新开始对话，清空历史并以新上下文继续。
- 请求中、成功、失败和未读状态有不同视觉反馈。

## 12. 暂不做的内容

第一版暂不加入：

- 多窗口同步。
- 用户账号和云端人设同步。
- 永久保存 API Key。
- 复杂语音输入和语音播报。
- 自主执行系统操作的 Agent 工作流。
- 知识库、文件检索和复杂多会话管理。
- 让 AI 直接控制任意前端 CSS 或执行任意代码。

这些内容会显著扩大安全和产品边界，等网页交互闭环稳定后再评估。
