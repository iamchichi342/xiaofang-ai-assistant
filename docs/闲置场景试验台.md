# 小方闲置场景试验台

## 1. 试验台目的

闲置场景试验台是网页开发版中的可视化验证区域，用于单独测试小方的闲置彩蛋，不需要等待自动闲置计时。

它解决三个问题：

- 快速验证场景元素是否容易理解。
- 观察眼睛目标、轻微转头和表情是否同步。
- 在接入自动随机调度前，先确认动画节奏和中断行为。

试验台不是正式用户功能，也不代表桌面版已经同步支持这些场景。当前版本先作为网页开发版的设计与调试工具。

### 隐形场景舞台

场景以小方的视觉中心为中心建立一个不绘制真实边框的隐形舞台：左右各约 `4cm`，上下各约 `3cm`。彩虹方块和小鸟的飞行基线位于小方中心上方约 `2.7cm`，也就是小方顶部上方约 `1.2cm`，避免被小方本体挡住。舞台使用裁切窗口实现，场景元素必须从边界外逐步进入，并在结束前完整离开边界。

这里的厘米是按浏览器 CSS 像素近似换算，用于统一视觉比例，不代表物理屏幕测量。

## 2. 使用方法

启动网页开发版：

```bash
python3 -m http.server 4177
```

打开 `http://127.0.0.1:4177/`，在页面下方的“闲置场景试验台”点击场景按钮。

可测试场景：

| 按钮 | 测试内容 |
|---|---|
| 彩虹小方巡游 | 无黑色外框的彩虹小方沿单峰弧线经过，小方持续注视方块与拖尾组成的整体中心，结束时恢复中性 |
| 小鸟编队 | 3 只小鸟从随机方向依次飞入、依次飞出，小方持续注视整个编队的中心 |
| 停止场景 | 立即清除当前场景，恢复小方的普通闲置状态 |

## 3. 点击反馈：被捏脸

“被捏脸”是点击反馈序列中的一次性互动动作，不作为长期表情保存。当前点击反馈按“被捏脸 → 喜悦 → 好奇 → 惊讶”循环；进入被捏脸反馈时按以下节奏执行：

1. 小方先短暂睁大眼，形成被碰到前的预备反应。
2. 一个较大的圆形触碰球从右上方伸出，缩小后落在小方右侧边缘中点，模拟伸手和捏住边缘。
3. 小方连续被轻晃两到三下，身体使用压扁、回弹、左右摆动表现受力。
4. 前几下保持惊讶、好奇和中性切换，最后用等宽圆头的弧线眼进入开心状态。
5. 动作完成后回到中性，并恢复正常鼠标注视。

动作期间左键点击和拖动被暂时锁定，避免打断状态机；右键菜单仍然可以打开和使用。

该动作采用“预备、压缩、回弹、跟随”的动画节奏。压缩与拉伸帮助用户感知受力，动作时序决定反馈是否容易读懂；同时继续遵守系统的 `prefers-reduced-motion` 设置。

## 4. 场景协议

每个场景由 `src/data/idle-scenes.js` 描述：

```js
{
  id: "rainbow-square",
  label: "彩虹小方巡游",
  duration: 6200,
  introExpression: "neutral",
  outroExpression: "neutral"
}
```

场景组件由 `src/components/IdleSceneManager.js` 负责：

- 创建和清理场景 DOM。
- 计算场景元素的实时位置。
- 把场景目标坐标传给 `assistant.setGazeTarget()`。
- 场景开始时触发表情。
- 场景结束时恢复普通闲置。
- 用户移动鼠标时立即中断场景。

视觉样式统一放在 `styles/idle-scenes.css`，场景元素必须满足：

- 使用 HTML、CSS、SVG 或 JavaScript 实现。
- `pointer-events: none`，不能挡住网页操作。
- 不依赖远程图片、视频或 3D 模型。
- 提供 `prefers-reduced-motion` 降级。
- 场景结束后清理自身 DOM。

## 5. 眼神与表情验收

### 彩虹小方巡游

- 彩虹小方没有黑色外框，并沿单峰弧线从隐形舞台边界外逐步钻入。
- 彩虹方块和完整拖尾都必须越过另一侧边界后才结束，不能在边缘突然消失。
- 小方从入场到离场始终保持中性，不因开始、重试或结束场景切换表情。
- 眼睛连续跟随彩虹方块与拖尾组成的整体中心，即使该中心尚在裁切边界外也不切换目标。
- 彩虹完整离开后直接保持中性，不额外触发喜悦弹跳或快速表情切换。

### 小鸟编队

- 鸟群由 3 只鸟组成，从左侧或右侧边界外随机进入。
- 鸟 1、鸟 2、鸟 3 按队形顺序逐只展现，不能整组突然出现。
- 领头鸟到达另一侧边缘后继续飞出，后续两只依次完整离场；不能让领头鸟停在边缘等待动画结束。
- 鸟群不能完全同步，至少有高度差和速度差。
- 小方始终注视三只鸟组成的编队中心；该中心尚未进入舞台或已经离开舞台时也不切换到单只鸟。
- 鼠标移动时场景立即消失，小方恢复默认行为。

## 6. 后续扩展规则

新增场景前先回答：

1. 场景元素是什么，用户能否在一秒内理解？
2. 小方在看什么，目标坐标如何连续变化？
3. 表情表达的是观察、惊讶、喜悦还是困倦？
4. 用户移动鼠标或打开面板时，能否立即中断？
5. 是否可以只用前端技术实现，并且不增加长期资源依赖？

推荐后续场景：

- 掉队小鸟追上鸟群。
- 纸飞机从小方头顶飞过。
- 一颗萤火虫在小方附近绕一圈。

## 7. 当前边界

当前试验台只在网页开发版加载。桌面版要同步这些场景，需要额外检查 Electron 透明窗口的场景绘制范围、点击穿透区域和多屏幕坐标行为。
