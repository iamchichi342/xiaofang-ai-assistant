# 只用眼神表达的小机器人：交互设计与实现教程

## 1. 目标效果

这个机器人不依赖嘴巴、手势或对白，主要通过以下变化表达“它正在看你、理解你、等待你”：

- 鼠标在机器人附近移动时，眼睛先跟随鼠标。
- 鼠标继续远离，眼睛到达可移动范围后不再继续偏移。
- 鼠标离机器人足够远时，头部才轻轻向目标方向转动。
- 鼠标停止后，机器人仍有眨眼、呼吸和轻微回正动作，不像一张静态图片。
- 点击、等待、加载成功和出错时，用不同的眼神节奏反馈状态。

最重要的动作原则是：**眼睛先动，头后动；头的动作比眼睛慢、幅度更小。**

这会产生一种自然的注意力转移：机器人先用余光看向目标，只有目标离得较远或停留较久时，才轻轻扭头确认。

---

## 2. 推荐实现路线

### 第一阶段：二维分层版，建议先做

需要准备：

1. 一张透明背景的机器人头部图片，不包含眼睛。
2. 两只独立的眼睛，或者由前端直接绘制的两个圆角矩形。
3. 可选的高光、阴影和头部蒙版。

页面结构分成三层：

```text
机器人容器
├── 头部底图
├── 眼睛可视区域（负责裁剪）
│   ├── 左眼
│   └── 右眼
└── 高光或玻璃质感层
```

优点：

- 鼠标跟随实时、轻量，没有视频解码延迟。
- 眼睛方向、眨眼和情绪都可以随时修改。
- 头部可先用 CSS 做轻微旋转，不需要马上生成视频。
- 手机端可以把鼠标输入替换为陀螺仪或触摸位置。

### 第二阶段：AI 方向帧版

当 CSS 旋转无法产生满意的侧脸、透视或光影变化时，再生成头部方向素材：

```text
最左 → 左前 → 正面 → 右前 → 最右
```

把这些方向帧去背景后拼成雪碧图。眼睛仍由前端实时控制，只有头部底图根据方向切换帧。

这比直接把整只机器人做成视频更灵活，因为眨眼、注视和状态反馈仍然可以由代码控制。

### 第三阶段：AI 视频版

只在需要自然的材质变化、柔软形变或明显侧脸时使用：

1. 生成绿幕或纯色背景视频。
2. 约束身体和镜头不动，只允许头部缓慢转动。
3. 提取视频帧并抠掉背景。
4. 删除形状跳变、眼睛漂移和轮廓不稳定的帧。
5. 拼成 WebP/PNG 雪碧图。
6. 根据目标方向选择对应帧。

不建议一开始就使用完整视频。这个角色的动作幅度很小，二维分层通常能完成 80% 以上的效果，同时更容易调试。

## 3. 交互区域设计

以机器人头部中心为原点，计算鼠标与机器人的相对位置：

```js
dx = mouseX - robotCenterX;
dy = mouseY - robotCenterY;
distance = Math.hypot(dx, dy);
```

把空间划分为三个区域：

| 区域 | 建议距离 | 眼睛 | 头部 |
|---|---:|---|---|
| 注视区 | 0～120px | 平滑跟随 | 保持不动 |
| 过渡区 | 120～320px | 接近最大偏移 | 延迟、轻微跟随 |
| 远距离区 | 320px 以上 | 保持最大偏移 | 缓慢转向目标 |

距离不能直接写死，因为机器人可能在不同屏幕上显示成不同尺寸。实际项目中建议以头部宽度为基准：

```js
const nearRadius = robotWidth * 0.8;
const farRadius = robotWidth * 2.2;
```

这样机器人缩放后，交互感觉不会变化。

---

## 4. 眼睛跟随算法

眼睛不能无限追着鼠标跑，必须限制在一个椭圆范围内。设眼睛最大横向偏移为 8px，最大纵向偏移为 5px：

```js
const length = Math.hypot(dx, dy) || 1;
const directionX = dx / length;
const directionY = dy / length;

const eyeStrength = Math.min(1, distance / nearRadius);
const eyeX = directionX * 8 * eyeStrength;
const eyeY = directionY * 5 * eyeStrength;
```

应用到眼睛：

```js
leftEye.style.transform = `translate(${eyeX}px, ${eyeY}px)`;
rightEye.style.transform = `translate(${eyeX}px, ${eyeY}px)`;
```

不要在 `mousemove` 中直接频繁修改 DOM。记录目标位置，然后使用 `requestAnimationFrame` 每帧更新一次。

眼睛适合使用较快的缓动：

```js
currentEyeX += (targetEyeX - currentEyeX) * 0.22;
currentEyeY += (targetEyeY - currentEyeY) * 0.22;
```

`0.22` 表示眼睛反应比较敏捷。数值越大，跟随越快。

---

## 5. 远距离轻微扭头

头部不应该和眼睛同时启动。先计算鼠标进入远距离区域后的进度：

```js
const headProgress = Math.max(
  0,
  Math.min(1, (distance - nearRadius) / (farRadius - nearRadius))
);
```

使用平滑曲线，避免刚越过边界就突然转头：

```js
const eased = headProgress * headProgress * (3 - 2 * headProgress);
```

然后计算头部目标角度：

```js
const maxHeadRotate = 5;
const targetHeadRotate = directionX * maxHeadRotate * eased;

const maxHeadLift = 3;
const targetHeadLift = directionY * maxHeadLift * eased;
```

头部使用比眼睛慢很多的缓动：

```js
currentHeadRotate += (targetHeadRotate - currentHeadRotate) * 0.055;
currentHeadLift += (targetHeadLift - currentHeadLift) * 0.055;
```

应用变换：

```js
robot.style.transform = `
  perspective(600px)
  rotateY(${currentHeadRotate}deg)
  rotateX(${-currentHeadLift}deg)
`;
```

推荐范围：

- 左右转头：`3deg～6deg`
- 上下抬头：`2deg～4deg`
- 眼睛横向偏移：眼睛容器宽度的 `12%～18%`
- 眼睛纵向偏移：眼睛容器高度的 `8%～14%`

动作过大会破坏“克制、聪明”的感觉，也容易暴露二维图片没有真实侧面的缺点。

## 6. 让动作有生命感

### 眨眼

眨眼不应固定每 3 秒执行一次，否则会显得机械。建议随机间隔：

```js
const nextBlinkDelay = 2200 + Math.random() * 4200;
```

一次眨眼可以采用：

```text
正常 → 迅速闭眼（70ms）→ 短暂停留（45ms）→ 睁开（110ms）
```

偶尔连续眨两次，但概率不要超过 15%。

### 呼吸和漂浮

整个机器人可以有非常轻微的上下浮动：

```text
位移：1～2px
周期：3.5～5 秒
```

鼠标正在快速移动时应减弱漂浮，避免动作互相打架。

### 眼睛的微小偏差

两只眼睛不要始终完全同步。右眼可以比左眼延迟一帧，或少移动 `0.2px～0.5px`。这种差异几乎看不出来，却能减少复制粘贴感。

## 7. 用眼神表达状态

建议先定义少量、清晰的状态，不要堆太多表情。

| 状态 | 眼神表现 | 头部表现 |
|---|---|---|
| 空闲 | 慢速眨眼，偶尔轻扫 | 基本回正 |
| 鼠标靠近 | 眼睛快速锁定鼠标 | 不动 |
| 鼠标远离 | 眼睛先到极限 | 之后慢慢跟上 |
| 悬停按钮 | 视线看向按钮 | 轻微偏头 |
| 鼠标按下 | 双眼短暂压扁 | 头部下沉 1px |
| 思考/加载 | 视线缓慢看向一侧或上方 | 极轻微倾斜 |
| 成功 | 眼睛短暂变宽，再恢复 | 回正速度略快 |
| 出错 | 两眼稍微靠近或向下 | 轻微低头 |
| 长时间无操作 | 慢眨眼，短暂看向别处 | 轻微漂移后回正 |

“情绪”最好由动作节奏产生，而不是把眼睛硬改成夸张符号。这个角色越克制，越容易显得有性格。

---

## 8. 推荐的状态机

前端不要让鼠标跟随、加载动画、眨眼和点击反馈同时争夺控制权。建议使用一个简单状态机：

```text
idle
  ├── pointer-active
  ├── thinking
  ├── success
  └── error
```

优先级建议：

```text
error > success > thinking > pointer-active > idle
```

眨眼属于可叠加动作，可以在多数状态中继续运行；但发生点击反馈或成功动画时，可以暂时延迟下一次随机眨眼。

## 9. 素材制作规范

### 最低素材需求

- `head-base.webp`：透明背景、正面头部、不含眼睛。
- `eye-left.svg` / `eye-right.svg`：白色或浅色眼睛。
- `head-highlight.webp`：可选，覆盖在眼睛上方。
- `shadow.webp`：可选，独立阴影层。

推荐导出尺寸：

```text
显示尺寸：120～240px
素材尺寸：显示尺寸的 2 倍
格式：WebP 或 PNG
色彩：sRGB
```

### 如果使用 AI 生成方向帧

建议先生成 9 帧，而不是直接生成几十帧：

```text
左 20°、左 15°、左 10°、左 5°、正面、右 5°、右 10°、右 15°、右 20°
```

提示词需要强调：

```text
Minimal friendly robot head, no mouth, expression only through two eyes,
fixed camera, fixed body position, identical lighting and proportions,
only the head slowly turns, clean solid green background,
no zoom, no camera movement, no morphing, no extra parts.
```

中文约束可以补充：

```text
镜头固定，机器人身体和画面位置完全不动，只允许头部轻微转向；
眼睛形状、距离、材质和光照保持一致；禁止缩放、镜头移动、形变和新增结构。
```

生成后重点检查：

- 两只眼睛间距是否跳变。
- 头部轮廓是否忽大忽小。
- 光源方向是否变化。
- 机器人中心点是否漂移。
- 左右转动是否视觉对称。

## 10. AI 视频转雪碧图流程

如果最终决定使用视频素材，可以采用以下流程：

```text
AI 生成 2～3 秒慢速转头视频
→ FFmpeg 提取帧
→ 色键抠掉绿幕
→ 对齐头部中心点
→ 删除异常帧
→ 选取 16～32 个有效帧
→ 拼接为雪碧图
→ 导出 WebP
```

FFmpeg 提取帧示例：

```bash
ffmpeg -i robot-turn.mp4 -vf "fps=20" frames/frame-%03d.png
```

如果素材已经有透明通道，直接进入对齐和拼图步骤。绿幕抠像应处理边缘去绿色污染，否则机器人轮廓在浅色背景上会出现绿色光晕。

使用雪碧图时，将头部角度映射到帧编号：

```js
const normalized = (headYaw / maxYaw + 1) / 2;
const frame = Math.round(normalized * (frameCount - 1));
```

注意：鼠标距离决定“转头参与度”，鼠标方向决定“选哪一帧”，这两个概念不要混在一起。

## 11. 完整更新逻辑示意

```js
const state = {
  mouseX: window.innerWidth / 2,
  mouseY: window.innerHeight / 2,
  eyeX: 0,
  eyeY: 0,
  headYaw: 0,
  headPitch: 0,
};

window.addEventListener("pointermove", (event) => {
  state.mouseX = event.clientX;
  state.mouseY = event.clientY;
});

function animate() {
  const rect = robot.getBoundingClientRect();
  const centerX = rect.left + rect.width / 2;
  const centerY = rect.top + rect.height / 2;

  const dx = state.mouseX - centerX;
  const dy = state.mouseY - centerY;
  const distance = Math.hypot(dx, dy);
  const length = distance || 1;
  const dirX = dx / length;
  const dirY = dy / length;

  const nearRadius = rect.width * 0.8;
  const farRadius = rect.width * 2.2;

  const eyeProgress = Math.min(1, distance / nearRadius);
  const targetEyeX = dirX * rect.width * 0.04 * eyeProgress;
  const targetEyeY = dirY * rect.height * 0.025 * eyeProgress;

  let headProgress = (distance - nearRadius) / (farRadius - nearRadius);
  headProgress = Math.max(0, Math.min(1, headProgress));
  headProgress = headProgress * headProgress * (3 - 2 * headProgress);

  const targetYaw = dirX * 5 * headProgress;
  const targetPitch = dirY * 3 * headProgress;

  state.eyeX += (targetEyeX - state.eyeX) * 0.22;
  state.eyeY += (targetEyeY - state.eyeY) * 0.22;
  state.headYaw += (targetYaw - state.headYaw) * 0.055;
  state.headPitch += (targetPitch - state.headPitch) * 0.055;

  leftEye.style.transform = `translate(${state.eyeX}px, ${state.eyeY}px)`;
  rightEye.style.transform = `translate(${state.eyeX * 0.97}px, ${state.eyeY}px)`;

  robotHead.style.transform = `
    perspective(600px)
    rotateY(${state.headYaw}deg)
    rotateX(${-state.headPitch}deg)
  `;

  requestAnimationFrame(animate);
}

requestAnimationFrame(animate);
```

## 12. 移动端处理

手机没有持续鼠标位置，可按优先级采用：

1. 手指按住或拖动时看向触点。
2. 页面滚动时看向当前重点内容。
3. 获得用户授权后，使用设备方向传感器。
4. 没有输入时运行空闲眼神动画。

不要在用户没有交互时直接请求陀螺仪权限。移动端的头部动作幅度应比桌面端再小约 20%，避免手机晃动导致角色持续抖动。

---

## 13. 性能与无障碍

- 使用 `pointermove`，统一支持鼠标、触控笔和部分触摸输入。
- 动画更新统一放入 `requestAnimationFrame`。
- 每帧只修改 `transform` 或雪碧图的 `background-position`。
- 避免在动画循环中重复读取多个布局属性。
- 页面隐藏时暂停非必要动画。
- 支持 `prefers-reduced-motion`，减少漂浮和转头，只保留必要反馈。
- 雪碧图优先使用 WebP，并准备 1x、2x 两种规格。

---

## 14. 推荐实施顺序

### MVP

1. 使用一个简单头部底图和两只独立眼睛。
2. 完成眼睛跟随、移动边界和随机眨眼。
3. 加入近、中、远三个距离区域。
4. 远距离时让整个头部产生 `3deg～5deg` 的缓慢转动。
5. 加入空闲、点击和思考三个状态。

### 视觉升级

1. 调整眼睛比例、间距和边缘质感。
2. 增加头部高光、内阴影和眼睛遮罩。
3. 生成 9 张稳定的头部方向帧，替换 CSS 透视旋转。
4. 如果方向帧仍不自然，再生成首尾帧可控的视频。

### 产品化

1. 将状态机与真实业务状态连接。
2. 让机器人主动看向输入框、提交按钮和错误提示。
3. 增加移动端触摸和设备方向输入。
4. 增加低性能模式和减少动态效果模式。

---

## 15. 最终建议

这个目标不需要先做 3D，也不应该先依赖完整视频。最稳妥的起点是：

```text
透明头部底图 + 两只独立眼睛 + 前端视线算法 + 轻微 CSS 头部转动
```

先验证“眼睛先锁定、远处才扭头”的动作节奏。动作感觉成立后，再决定是否值得生成 AI 方向帧或视频雪碧图。对于这种只有眼神的小机器人，交互节奏通常比素材复杂度更重要。
